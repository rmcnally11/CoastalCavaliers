--------------------------------------------------------------------------------
WHAT CHANGED FROM THE PROMPT, AND WHY
--------------------------------------------------------------------------------

The prompt said "organize your CSS, JS and images into /assets". You had none
of those as separate files — the whole site was a single 540 KB HTML page with
sixteen images encoded inside it as base64 text.

The instinct was right, for a better reason than it gave:

  · base64 is about a third larger than the raw bytes
  · a browser re-downloads embedded images on every single visit
  · git re-stores all 540 KB on every commit, even a one-word copy edit

So I extracted the images to real WebP files. 471 KB of base64 became 196 KB of
image files — a 58% reduction — and the HTML dropped from 540 KB to 40 KB.

Everything else in the prompt I did as asked.

--------------------------------------------------------------------------------
IF YOUR SITE IS SERVING THE WRONG FILES — READ THIS FIRST
--------------------------------------------------------------------------------

Symptom: the homepage shows JavaScript as plain text, starting "const CACHE=".
Or /manifest.json comes back as 700 KB. Or files appear under wrong names.

Netlify is not broken. Your BROWSER is not asking Netlify.

An earlier build of the app registered a service worker at /sw.js. A service
worker takes the scope of the folder it is served from, so one at the root
claims the ENTIRE DOMAIN. Once installed, it answers every request from its own
cache before the network is ever touched, and it falls back to serving the app
for any navigation it cannot resolve. That is precisely the symptom.

This build fixes it three ways:

  1. The app now registers at /app/sw.js with scope /app/, so it can only ever
     control the app.
  2. There is a KILL-SWITCH at /sw.js. It caches nothing. On activation it
     deletes every cache on the origin, unregisters itself, and reloads open
     tabs. Anyone already affected is cleaned the next time they visit.
     DO NOT DELETE THIS FILE. Browsers holding the bad worker will keep
     serving stale pages until they fetch it.
  3. site.js also removes, on load, any worker whose scope is not /app/.

TO CLEAN YOUR OWN BROWSER RIGHT NOW, without waiting:

  Chrome / Edge   F12 -> Application -> Service Workers -> Unregister
                  then Application -> Storage -> Clear site data
  Safari          Develop -> Empty Caches, then quit and reopen Safari
  Any browser     open the site in a private window to confirm the real state

A private window has no service worker, so it always shows you what Netlify is
actually serving. Use it to check every deploy from now on.


--------------------------------------------------------------------------------
BECAUSE IT IS GOING TO GITHUB — three things
--------------------------------------------------------------------------------

THE CODE ITSELF DOES NOT CHANGE. Static files are static files, and Netlify
serves them the same whether they arrive by drag-and-drop or by git push.
But three things do change:

1. MAKE THE REPOSITORY PRIVATE.

   assets/js/site.js contains your n8n endpoint. That is unavoidable for a
   static site — the browser has to know where to POST, so anyone can read it
   in view-source whether it lives in a repo or not.

   But a GitHub repo is far more discoverable than a minified JS file. Bots
   scrape public repos looking for exactly this. Someone could POST junk to
   the webhook and fill your Airtable with garbage.

   Private costs nothing. Netlify connects to private repos identically.
   In GitHub Desktop, leave "keep this code private" TICKED when publishing.

2. A .gitattributes FILE IS NOW INCLUDED.

   It normalises line endings and marks images as binary, so git does not
   mangle a .webp or produce noisy diffs if you ever edit from Windows.
   You will never think about it again.

3. THE ROOT icons/ FOLDER WAS REMOVED.

   Nothing referenced it — 165 KB of duplicates of app/icons/. Worth deleting
   now, because git keeps every version of every file forever.

ALSO WORTH KNOWING

   Netlify will build every branch and every pull request by default, each
   getting its own preview URL. Useful for testing a change before it goes
   live. If you would rather it only built main:
     Site configuration -> Build & deploy -> Branches -> Production branch only

   app/index.html is 713 KB and still has everything embedded. Git re-stores
   the whole file on every commit that touches it. Fine for now. If the app
   starts changing often, extract its assets the way the site's were.

--------------------------------------------------------------------------------
STEP 1 — PUT THE FILES SOMEWHERE
--------------------------------------------------------------------------------

Download coastalcavaliers_REPO.zip and unzip it. You will get a folder with
index.html at the top level. Put it wherever you keep code — for example:

  ~/Projects/CoastalCavaliers

--------------------------------------------------------------------------------
STEP 2 — PUSH IT  (the easy way)
--------------------------------------------------------------------------------

If you have GitHub Desktop, this is far less error-prone than the terminal:

  1. GitHub Desktop → File → Add Local Repository → choose the folder
  2. It will say "this is not a git repository" → click "create a repository"
  3. Publish repository → uncheck "keep this code private" if you want it public
     → name it CoastalCavaliers
  4. Done.

If the repo at github.com/rmcnally11/CoastalCavaliers.git already exists and
is empty, use "Publish" and point it there, or follow the terminal route below.

--------------------------------------------------------------------------------
STEP 2 ALTERNATIVE — PUSH IT  (terminal)
--------------------------------------------------------------------------------

Open Terminal, cd into the folder, then run these one at a time.
Read each before you run it.

  cd ~/Projects/CoastalCavaliers

    # confirm you are in the right place — you should see index.html
  ls

    # start tracking this folder with git
  git init

    # stage everything except what .gitignore excludes
  git add -A

    # take the first snapshot
  git commit -m "Initial commit: static site, assets extracted"

    # name the branch main (GitHub's default)
  git branch -M main

    # point at your repo
  git remote add origin https://github.com/rmcnally11/CoastalCavaliers.git

    # send it
  git push -u origin main

If the last command errors with "updates were rejected" the repo already has
something in it (usually an auto-created README). Either of these fixes it:

  git pull --rebase origin main
  git push -u origin main

Or, if you are certain the repo is empty and want to overwrite:

  git push -u origin main --force

GitHub will ask for a username and password. The password is NOT your account
password — it is a personal access token. Create one at:
  github.com → Settings → Developer settings → Personal access tokens
  → Tokens (classic) → Generate new token → tick "repo" → copy it
Paste that when prompted. macOS will remember it in the Keychain.

--------------------------------------------------------------------------------
STEP 3 — CONNECT NETLIFY
--------------------------------------------------------------------------------

  1. app.netlify.com → your coastalcavaliers.com site
  2. Site configuration → Build & deploy → Continuous deployment
  3. "Link repository" → GitHub → authorise → choose CoastalCavaliers
  4. Build settings:
        Base directory      (leave empty)
        Build command       (leave empty)
        Publish directory   .
  5. Deploy

Netlify reads netlify.toml for everything else.

--------------------------------------------------------------------------------
STEP 4 — THE THING THAT WILL BITE YOU
--------------------------------------------------------------------------------

Once the repo is connected, STOP dragging folders into Netlify.

A manual drop and a git push will fight. The next push silently overwrites
whatever you dropped, and you will spend an hour wondering why your change
disappeared. From now on:

  git add -A
  git commit -m "what changed"
  git push

That is the whole deploy process. Netlify picks it up in about a minute.

--------------------------------------------------------------------------------
STEP 5 — THE OTHER THING THAT WILL BITE YOU
--------------------------------------------------------------------------------

netlify.toml caches /assets/* for a year and marks it immutable. That makes
repeat visits fast, but it means:

  IF YOU CHANGE AN IMAGE, CHANGE ITS FILENAME.

Otherwise browsers keep serving the old one for up to a year. Copy and HTML
edits are unaffected — those are never cached.
